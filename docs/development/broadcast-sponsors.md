# Studio draft and sponsor slideshow

Studio uses a 1920x1080 transparent canvas with a 1920x320 bottom strip. Its top-center 400x68 slot contains only uploaded sponsor artwork. The layout includes coaches and bans above picks, vertical hero labels, blue/red player ribbons, match/game and score bars, team logos and team-name ribbons, and a gold phase/timer center. There is no authored league logo or BPM display. Classic retains the actual display2 geometry; Arena retains its separate blue layout. Original display URLs stay fixed.

Open `/broadcast-themes.html`, find **Sponsor slideshow**, and click **Preview Studio draft**. Add one PNG, JPEG, WebP or GIF at a time (3 MiB per logo, up to 20). Uploads save immediately. Reorder/remove, change the 2–60-second interval or toggle display, then click **Save slideshow**. Save pending edits before uploading another logo. A single logo holds; multiple logos rotate in saved order. The slot stays blank when disabled or empty. Logo images use contain sizing and preserve transparency. Previewing Studio does not activate it globally; the existing theme activation button still controls the selected broadcast theme.

Settings are global to new Studio draft outputs, including normal and six-ban formats, and independent of match state. Classic, Arena, roster and legacy display outputs do not render this sponsor slot. Legacy roster sponsor settings remain separate. Changes made here update all open Studio draft sources after acknowledgement.

`GET /api/broadcast-sponsors` returns `{data,revision}`. `POST /api/broadcast-sponsors/logos` accepts multipart field `logo`. `PUT /api/broadcast-sponsors` accepts `{enabled,intervalSeconds,logoIds}` for ordering/removal. Writes require the latest `If-Match` revision and return 409 for stale operator settings. State is committed atomically before `broadcast_sponsors_update` is sent over the existing WebSocket. Failed uploads/commits do not publish a playlist and clean up their unpublished file.

Runtime files are `runtime/broadcast-sponsors.json` and `runtime/sponsor-logos/`, both ignored by Git. Back up both together. Startup validates saved settings and does not silently replace a corrupt file. Logo uploads use generated names, raster-signature checks, and a size limit; SVG/HTML uploads are not accepted. Removed files are deleted after the settings commit; an unlink failure does not undo an acknowledged save. This tool's existing local/LAN access model remains unchanged.

The renderer fetches settings on mount/recovery, consumes the existing draft socket's sponsor events, and polls every five seconds for recovery. Playlist changes preserve the current logo when possible. A failed logo retains the last decoded logo and advances on the next interval; a failed initial logo leaves the slot blank. It never writes match, draft or sponsor state. Settings and playlist order survive restart; slide elapsed time does not.

Verification uses isolated data, real upload and persistence routes, browser decoding, rotation, reorder, enable/disable, stale-editor rejection, recovery, and identical draft state before/after sponsor edits. Browser composition is checked with synthetic artwork. Actual Windows/OBS rendering, font availability and final sponsor assets require checking on the production PC.
